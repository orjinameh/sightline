## Submission format — exact required fields

Announcement, participation steps verbatim:

> 1. **Build** a template using Hyper Elements.
> 2. **Publish** your source code in a public GitHub repository with a clear README.
> 3. **Star** the [Hyper Elements GitHub repository](https://github.com/hyper-elements/hyper-elements).
> 4. **Submit** your project through the [official challenge submission form](https://github.com/hyper-elements/hyper-elements/discussions/new?category=challenge-submissions).

FAQ #12 — the form's fields, verbatim:

> - **Challenge:** Select the Hyper Elements Template Challenge from the dropdown.
> - **Project name:** The name of your template.
> - **Project description:** A brief explanation of what you've built.
> - **GitHub repository:** A link to the public repository containing your template's source code.
> - **Hyper Elements implementation:** A brief explanation of how you've used Hyper Elements in your project.
> - **Live preview (optional):** A link to your template if it's publicly accessible.

FAQ #12 — README requirements, verbatim:

> Your repository must also include a README with:
> - **Preview:** A screenshot, GIF or video showcasing the completed template.
> - **Hyper Elements implementation:** An explanation of how Hyper Elements was used.
> - **Setup instructions:** Clear instructions on how to run or reproduce your template.

FAQ #11 — the form ends with confirmations: *"You'll also need to confirm that you've starred the Hyper Elements

the challenge requirements."*

FAQ #14: *"Do I need to deploy my template? — No. A live deployment is not required to participate. … If your

## Judging criteria — verbatim, WITH weights

**Announcement (short form), verbatim:**

> Submissions will be evaluated by Unlayer's core team based on **originality, design quality, practical value,
> effective use of Hyper Elements and overall execution**. Technical complexity alone will not determine the winners.

**FAQ #22 (full form), verbatim:**

> All eligible submissions will be reviewed by Unlayer's core team based on the following criteria:
> - **Originality:** How creative and original is the template's concept?
> - **Design quality:** Is the template visually polished, well-structured and thoughtfully designed?
> - **Practical value:** How useful is the template, and could other developers realistically reuse or build upon it?
> - **Use of Hyper Elements:** How effectively is Hyper Elements integrated into the template's implementation?
> - **Overall execution:** Is the template functional, well-presented, properly documented and easy to understand or reproduce?
>
> Submissions will be evaluated holistically, with no preference given to any particular template type or output format.

### ⚠️ Weights: none are published — this is a documented gap, not an unknown we can invent

No percentage, point value, ranking, or tie-break rule appears in the announcement, the FAQ, or anywhere else in the
event's ecosystem as of 2026-11-23. The only weighting statement is the explicit **"evaluated holistically"** above.
Two further statements constrain the shape of the rubric:

- FAQ #23, verbatim: *"Do more complex templates have a better chance of winning? — Not necessarily! Technical
  complexity alone will not determine the winners. A simple, well-designed template with a strong concept, practical
  value and thoughtful use of Hyper Elements can be just as competitive as a more complex project."*
- FAQ #21: *"Are there different prize categories? — No. There are no separate categories. All eligible templates
  will be considered together, and five winning submissions will be selected."*

**Downstream rule:** idea-forge's rubric must model these as **five equally-weighted criteria** (the only defensible
reading of "holistically" + "no categories"), with a note that `Originality`, `Design quality` and
`Use of Hyper Elements` are the three the field demonstrably under-serves (see `prior-art.md`), and that
`Overall execution` explicitly contains **documentation + reproducibility**.
